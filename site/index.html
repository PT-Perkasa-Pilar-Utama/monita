Find out a service is down before your users write to you.

Monita checks every URL and cron job your team runs. When a check fails twice in a row, it opens an incident, emails the owner, posts to your chat, and puts the incident on your public status page.

What Monita does when a check fails

This is the sequence for an HTTP monitor that checks every 30 seconds. One failed check does not wake anyone, because a single dropped request is common. The second one does.

api.example.com/healthz
    1. The first check failsHTTP 503. Monita waits for the next check.
    2. The second check failsTwo in a row open an automatic incident.
    3. The owner hears about itEmail and a webhook to Slack or Teams, through an outbox that retries.
    4. Users see itThe status page shows the incident and every update the team posts.
    5. The first passing check closes itMonita sends a recovery alert with the downtime.

    Cron jobs report in, and Monita notices when one stops

    A heartbeat waits for a job to call its URL. When a ping does not arrive by the deadline, Monita opens an incident. A job can also report its own failure, and the first kilobyte of its error output becomes the incident's cause.

    URL=https://monita.example.com/ping/<token>
if ! out=$(backup.sh 2>&1); then
  printf '%s' "$out" |
    curl -fsS -m 10 --data-binary @- "$URL/fail"
  exit 1
fi
curl -fsS -m 10 "$URL"

    Pings arriving on time

    Your team and your users read the same incident

    Each project gets a public status page. It shows 90 days of uptime for the services you mark public, every open incident, and the updates your team posts. Users can also report a bug from that page, and the tech lead sorts the reports on the ticket board.

    Inside Monita, each monitor has a response-time chart, availability for today, 7, 30 and 365 days, and the full list of checks.

    Built to run on a server you already have

    A single binary

    Monita is a Rust program that stores everything in a SQLite file. It does not need Docker, a separate database or a message queue.

    Daily backups

    Monita copies its database file every night and keeps the last seven copies. A backup restores by copying the file back.

    Checks from inside your network

    Monita runs next to your services, so it can check internal addresses that an outside service cannot reach.

    Alerts that do not block checks

    Alerts go through an outbox. A slow mail server delays an email, but every check still runs on time.

    Bounded by design

    Every list has a hard limit and every background job works in batches, so a large project does not slow the pages down.

    The source is on GitHub. You can read every check, change it, and run it without a subscription.

    Three commands install it on Linux

    monita setup asks for your public URL and mail server and creates the first admin. monita service install creates the system user and the systemd unit, starts Monita and waits until it answers.

    Read the install guide
    root@monitor-vm
    install -m 0755 monita /usr/local/bin/monita
sudo monita setup
sudo monita service install
monita is running: http://127.0.0.1:8080/healthz
