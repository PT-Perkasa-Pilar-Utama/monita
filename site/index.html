Know a project is down before its users tell you.

Monita checks your URLs and cron jobs, opens an incident, alerts the people who own it, and keeps a public status page honest. One self-hosted binary, one SQLite file.

Try the demo Get started GitHub

HTTP monitors

Every 30 seconds to 5 minutes. Status codes, a keyword in the body, a timeout. Two failures in a row open an incident; the first pass closes it.

Cron heartbeats

A job calls its URL when it finishes. A late job, or a call to /fail with the error as the body, opens an incident at once.

Alerts that reach people

Email and a webhook per severity, sent through an outbox, so a slow mail server never delays a check. Slack and Teams work as-is.

A status page per project

90 days of uptime, live incidents and your updates, plus a JSON endpoint to build your own widget.

Bug tickets from users

Your backend hands each user a ref ID. They report bugs through the status page or your app; you sort them on a kanban.

Light to run

One Rust binary with the database in one file. monita setup and monita service install put it on a Linux VM.

One line in a cron job

Ping on success. Send the error on failure; its first kilobyte becomes the incident's cause.

if backup.sh; then curl -fsS -m 10 https://monita.example.com/ping/<token>
else curl -fsS -m 10 https://monita.example.com/ping/<token>/fail; fi

Three commands to production

On a Linux VM, behind your HTTPS reverse proxy.

install -m 0755 monita /usr/local/bin/monita
sudo monita setup            # URL, SMTP, folders, first admin
sudo monita service install  # systemd, started now and at boot
